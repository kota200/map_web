RNA-seq Local

Browser-first RNA-seq analysis with a stable kallisto workflow.

Home Help

Manual

The current stable workflow runs the kallisto command-line engine as WebAssembly in your browser.

The app is designed so that transcriptome, index, FASTQ, and result files remain on the user's computer. The web server supplies only the application files and WebAssembly runtime.

Analysis Methods

Stable · Recommended

Kallisto in browser

Uses a transcriptome reference and pseudoalignment. The primary outputs are transcript-level estimated counts and transcript TPM.

This is not conventional genome alignment, and its transcript TPM must not be presented as the same quantity as a gene TPM derived from featureCounts.

Experimental · W5 passed · W6 pending

HISAT2 + featureCounts in browser

The experimental workflow aligns reads to a genome, assigns alignments to annotated features, and reports gene-level raw counts, Length, and gene TPM.

It accepts only hosted prebuilt HISAT2 indexes in the browser. The current catalog is a synthetic fixture; no production biological reference is configured.

D1/D2 engineering accepted

Desktop app

The native desktop workflow supports custom index construction, large references, and long-running jobs. CI produced verified unsigned installers; public distribution still requires platform signing, macOS notarization, and release approval.

Requirements

  • Modern browser: Chromium is the supported family. Firefox 141 passed the small W6 CI gates and is Experimental because representative scale is unmeasured. Safari is Unsupported for this gate: real Safari is unmeasured, while the Linux WebKit 26 diagnostic lacked OPFS and the packaged Kallisto runtime.
  • WebAssembly runtime: kallisto/kallisto.js and kallisto/kallisto.wasm must be deployed with the app.
  • Memory: index construction can require substantial RAM. The browser and operating system must have enough free memory for the selected transcriptome and generated index.
  • HTTP/HTTPS: serve the app from a web server; do not open index.html directly with file://.
  • Capability result: the Home page reports WebAssembly, Worker, pthread isolation, checksum, and browser-storage capabilities before offering the experimental HISAT2 workflow.

Reference and Index

Build from FASTA

Select a transcriptome FASTA or FASTA.gz. Do not use a genome FASTA. The default k-mer size is 31.

Existing Index

You can skip index construction by selecting a previously created kallisto .idx file. Use an index created by a compatible recent kallisto version; building the index in this app is the safest option.

Generated Index

After construction, the index remains local in browser memory and can immediately be used for quantification. You can also download it for reuse.

Target Names

Use Make repeated target names unique only when the transcriptome contains duplicate FASTA identifiers and you intentionally want kallisto to rename them.

RNA-seq Reads

FASTQ and FASTQ.gz are supported. For paired-end data, select matching R1 and R2 files in each sample card. If one biological sample is split across lanes, select all of its lane files in that card; files are paired by selection order.

Use + Add sample for additional biological samples. Samples run sequentially in one WebAssembly Worker to keep memory bounded; they are never quantified concurrently.

Quantification Parameters

Threads

Controls kallisto worker threads when the WebAssembly build supports pthreads. The v10 build supports up to eight quantification workers. Increasing the thread count does not necessarily result in a substantial speedup because performance depends on the workload and system architecture.

Bootstrap Samples

Default is 0. Increase this only when bootstrap abundance estimates are required; additional bootstraps increase runtime.

Strandedness

Select unstranded, FR-stranded, or RF-stranded according to the RNA-seq library protocol.

Single-end Reads

Single-end mode requires the estimated average fragment length and its standard deviation.

Optional fastp

Kallisto fastp defaults OFF to preserve the established input path. When enabled, samples run sequentially through fastp before Kallisto; JSON, HTML, QC summary, and cleaned gzip FASTQ are downloadable. Cleaned FASTQ remains in browser storage until you use the explicit delete action, replace it with another run, or leave the page.

Plaintext Output

The browser build always uses --plaintext. This avoids an HDF5 dependency and produces abundance.tsv.

v10 performance build

The v10 Wasm runtime is compiled with -O3, LTO (-flto), WebAssembly SIMD128 (-msimd128), and the vendored zlib-ng library in zlib-compatible mode.

HISAT2 Web Limits and Desktop Recommendation

The experimental HISAT2 form performs a storage-and-scale preflight before downloading a reference or starting a job. Its estimates are conservative heuristics, not measured percentages or a guarantee.

  • Hosted reference envelope: an index/annotation payload at or above 1.5 GiB is rejected by the current Web gate. HISAT2-Wasm and featureCounts-Wasm each have an audited 2 GiB linear-memory maximum, but peak biological-data usage is not yet measured.
  • Storage headroom: the form reserves the hosted package, estimated decompressed/cleaned FASTQ and SAM, plus 256 MiB. A job is rejected when the browser reports less available storage.
  • Desktop recommendation: compressed input at or above 2 GiB, or an estimated temporary footprint at or above 2 GiB, is beyond the measured small HISAT2 Web envelope. Use the future desktop workflow for such jobs after it is released; there is no desktop installer yet.
  • Current production status: only the 4,203,807-byte synthetic chrTiny package has passed end to end. Do not use it for biological interpretation.

For context, the instrumented W6 Kallisto measurement successfully processed the supplied 3.10 GB paired gzip FASTQ against a 135.2 MB Arabidopsis transcriptome index in Chrome in 882 seconds with one thread. The index build reached a 1,120,010,240-byte Wasm linear-memory high water; quantification showed a rounded 747.8 MiB high water. These are Wasm allocation measurements, not OS resident-memory measurements, and do not validate HISAT2 at the same scale.

Local Processing and Privacy

The application uses browser File/Blob objects and Emscripten WORKERFS. Selected biological files are mounted read-only inside a Web Worker and are not posted to the server by this application.

The browser still downloads the static HTML, JavaScript, and WebAssembly application files when the site is opened. The experimental HISAT2 workflow also downloads the selected hosted index and annotation. These downloads are different from uploading the user's RNA-seq data.

No telemetry is added by this build.

Outputs

  • abundance.tsv: transcript-level abundance estimates including estimated counts and TPM.
  • run_info.json: standard kallisto run metadata and mapping/pseudoalignment summary.
  • browser_performance.json: browser wall-clock timings for Wasm initialization, index loading, FASTQ processing/pseudoalignment, EM, output generation, total runtime, read throughput, and Wasm linear-memory high water. The memory value is an allocation measure, not OS resident memory.
  • counts_matrix.tsv / tpm_matrix.tsv: batch matrices aligned and validated by target_id; estimated counts retain kallisto's fractional values.
  • transcripts.idx: available for download when an index is built in the browser.
  • HISAT2 workflow: per-sample counts, counts with gene TPM, raw featureCounts tables and summary, HISAT2 summary, run metadata and logs; optional fastp cleaned FASTQ/JSON/HTML; batch matrices and manifest.

Troubleshooting

Runtime not found

Run build/build-wasm.sh and copy the generated kallisto.js, kallisto.wasm, and any generated worker helper files into kallisto/.

Threads do not work

A pthread-enabled WebAssembly build requires cross-origin isolation. The included Apache .htaccess sets COOP and COEP headers.

Out of memory

Reduce concurrent applications, start with one thread, and test a smaller transcriptome. Kallisto index output is currently memory-backed. HISAT2 reference payloads at or above 1.5 GiB are blocked before execution.

Stopped analysis

The Stop button terminates the Web Worker. Partial outputs are discarded.
